# 0106 — Run Existing Approach B on the New Local 2D B/D Dataset

**Purpose:** One bounded, faithful Approach B (`LB`) training-and-evaluation run on the **already collected new 2D B/D dataset**. This is a run/integration task, **not** a methodology review, label audit, data-generation task, or redesign.

## 0. Non-negotiable scope

1. **Only Approach B.** Use the existing P17 production B variant `LB`: `abc7_models.ModelBC7(kind="B", couple="none", order="pred")`, with its existing unique-factor negative log-likelihood and P17 B optimizer/settings. Do **not** switch to `FULLB`, Approach C or Approach D; no architecture, loss, energy-factor, feature, or search-policy redesign.
2. **Only the new, already collected 2D dataset** generated by `bd_core.py` / `bd_2d.py` / `bd_run.py`, identified by `BD_GEN_V1` and `BD_BINARY_BUDGET_V1`. Do **not** use historical P13–P17 data for any training, calibration, validation or test examples. You may read historical B *source code* solely to reuse the implementation.
3. **Local workstation only.** No SSH, server, remote GPUs, external jobs, copying data from the server, or querying server status. Use only a complete dataset already present on a locally mounted filesystem. Never guess or substitute a data path.
4. **Use recorded labels as-is.** The dataset's recorded `y` values and the source's intended meaning are authoritative. **No label audits, reclassification, disagreement analysis, relabeling, teacher verification, new queries, or reinterpretation.** Keep original records read-only. A missing label is missing; never fabricate one.
5. **Do not touch** Approach D, G4, C3/W-ROOT/W-TRANSFER catalogs, swept volumes, local/global similarity, motion retrieval, connector/home/continuous-transition code, destination proposals, the generator, or 3D work. Continuous A→B transitions remain the agreed future requirement; **do not implement or revisit them in this task**.
6. Work in `Narendhiranv04/latent-causal-tamp`, on a dedicated branch `approach-b-bd2d-v1` based on `dataset-bd-v1` (or the equivalent verified B/D dataset-code commit if the local branch is arranged differently). Do not merge into `main` or `approach-d-v1`. Commit and push only this dedicated branch when the run and checks succeed.

## 1. Locate and freeze input (no new collection)

- Check `git status`, current branch, SHA, and whether `bd_core.py`, `bd_2d.py`, `bd_run.py`, `p17_b.py`, `abc7_models.py`, `unique_factor.py`, `unique_factor_keyed.py` exist.
- Locate **existing local** dataset directories containing `MANIFEST.json`, `SPLITS.json`, `roots/*.json`, and `witnesses/` (if referenced). Do not access `/data/user1/...` remotely; it is only usable if this is genuinely a local mounted directory. Prefer a supplied local path or discover among existing local project directories.
- Record input directory, exact file hashes, root count, and whether split assignments are present. This is **input provenance**, not label analysis.
- If no usable new dataset exists locally, **stop with `BLOCKED_LOCAL_DATASET_NOT_FOUND`**; identify the expected files and nothing else. Do not run on historical data, invent a smoke dataset, or generate replacement data.
- Respect `SPLITS.json`'s **IID** root/family-grouped train/val/test split. No leakage across splits, no moving test examples into training, no split reseeding. Only apply an explicit deterministic family-group split if the new dataset itself has no usable split manifest; disclose the exact fallback. If training or validation lacks records, stop with a concrete blocker rather than quietly training on test data.

## 2. Minimal data adapter: new B/D JSON → existing B learner

Implement the smallest possible local 2D B adapter, e.g., `bd_b.py` (one file plus focused tests). **Do not modify `bd_2d.py` or original saved root records.**

Map source fields without changing their semantics:

- Scene, target/goal, robot initial `q0`, object identifiers, geometry, and intended object order from each stored root.
- `labels.original.y` → empty-repair original-target outcome.
- `labels.B` → each **already recorded** ordered corrective sequence and its stored binary `y`; preserve order, destinations, and the provided sequence length. Do not synthesize additional B labels.
- `labels.D` → optional **already recorded** edited-scene observations when the existing B scene-outcome encoding needs them; these are auxiliary observations for B, not D training. Use recorded edit mappings only.
- If an omission variable maps to an **already recorded exact physical sequence**, reuse that recorded `y`; otherwise treat it as unobserved. Do not assume omissions are infeasible, and do not run the teacher.
- For a valid positive sequence with recorded travel metadata, use only fields that the unchanged existing B objective actually reads; **keep existing production LB coefficients** (`lambda_static=lambda_travel=0`).
- Reuse `p17_b`'s B sequence encoding, `p10c_train_eval._record`/`learn_data` feature pipeline and `p17_b.prepare`/`fit` only as applicable. If their input schema differs (`start_stratum` vs `stratum`, root seed metadata, root ID, etc.), adapt **metadata in memory only**. Do not mutate generator files.
- The new B/D protocol permits up to **6 obstacle relocations plus the final target action**, while historical `p17_b.layout` has `MOVE_CAP=4` and `MAX_ACTIVE=9`. **Do not silently discard, truncate or relabel sequences of lengths 5–6.** Create a narrowly scoped new-layout adapter for the new data if needed, preserving B's existing model and loss; cap the optional auxiliary observation slots deterministically where mathematically required while always retaining the original-target and full repair outcome. Explicitly report any sequence length that genuinely cannot be represented instead of silently skipping it. Keep historical P17 code and checkpoints unchanged.
- Any appearance/visual representation must use the current project's existing deterministic rendering/feature pipeline; do not switch to new pretrained models or initiate unrelated GPU-heavy embedding work. Report a concrete blocker if the original B encoder cannot receive valid features locally.

## 3. Run only production Approach B

- Train **one seed (`seed=0`)** of `LB` from scratch on the new dataset's training split. Do not mix in old P13–P17 examples or initialize with their trained B weights.
- Reuse the current `p17_b.fit('LB', ...)` implementation and its defaults: AdamW `lr=1e-3`, weight decay `1e-4`, root-batch `12`, gradient clip `10`, validation evaluation every `20` updates, early-stopping patience `15`. Set a **maximum of 3,000 updates**, with the existing early-stopping behavior. Do not change hyperparameters based on test-set performance.
- Use the existing production-B unique-factor NLL. Do not add classification auxiliaries, novel energy losses, correction-order losses, or a search/planner stage.
- Validate on the given IID validation split, then evaluate the selected checkpoint on the untouched IID test split. Produce only the standard minimal B outcomes: validation NLL, test NLL, test binary prediction metric(s) supported by the existing scorer, and predictions for the dataset's B sequence records. If a metric is inapplicable, report `N/A`—do not invent it.
- For roots with more than one candidate sequence, save their original candidate order, predictions and labels as **unmodified records** for reproducibility; do not reinterpret correctness of the labels or promote this run into a full repair-execution claim.
- Use local CPU/GPU only; keep run-time/resource use visible. In case of memory/resource failure, make one minimal batching/memoization adjustment (preserving the objective and effective per-root weighting) or stop with the exact blocker; no methodology expansion.

## 4. Verification and outputs

Minimal automated checks:

1. Input comes exclusively from the selected `BD_GEN_V1` 2D directory; no old-dataset samples entered the train/validation/test loader.
2. IID train/val/test root/family IDs are disjoint.
3. Source `y`, sequence order and destination cells survive conversion byte-for-byte or value-for-value; no label rewriting.
4. Length-5/6 sequences, if present, are not silently lost; the full sequence is still the prediction target.
5. Recorded feature and target dimensions are accepted by the unchanged production B network.
6. Test examples are never used for optimization or early stopping; model/checkpoint hashes and seed are recorded.

Write new run artifacts **only** under `runs/approach_b/bd2d_lb_v1/` (checkpoint, training curve or log, `RUN_MANIFEST.json`, `EVAL.json`, predictions). Add a concise numbered report `responses-phases/0106_B_NEW_2D_DATASET_RUN.md` with exact dataset path/hash, counts of loaded root records per split (not label-distribution analysis), commands, training status, final numerical results, tests, checkpoint hash and remaining blockers. If required, put small visualizations of the loss curve under `visualizations/approach_b/bd2d_lb_v1/`.

Run the focused tests and, where practical, relevant existing Approach B regressions. Do not rerun historical physics/teacher suites or server jobs.
